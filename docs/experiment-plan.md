# Skill 演化实验思路

想看代码 agent 能不能从前面的任务中总结经验，持续修改 `SKILL.md`，帮助解决后面的任务。模型和配套工具保持固定，只让 skill 文档演化。

## 三种方式的对比

| 方式 | 一道题怎么做 | 候选间的关系 |
| --- | --- | --- |
| 五路并行 | 同时生成 5 条轨迹，各自反思，最后选最好的一条提交 | 五路独立求解 |
| 五路串行共享 | 依次生成 5 条轨迹，每条都反思，最后选最好的一条提交 | 后一路参考前面轨迹的操作、补丁和反思 |
| 单路反思 | 生成 1 条轨迹，反思后直接提交 | 没有多路搜索和选择 |

三种方式都使用 `qwen3.8-max`，关闭 planner，每条轨迹最多反思 5 次，可以提前停止。串行每一路仍从该题原始环境开始，不直接继承前一路的工作区。

单路预算统一为：初始求解最多 60 步，每轮反思后修改最多 20 步，理论最多 160 个求解步骤；反馈模型请求另计。单条命令超时 180 秒，初稿和全部反思共用 30 分钟预算。串行五路各自使用这份预算，五路合计消耗仍高于单路，比较时同时报告 token 和耗时。

训练阶段一道题结束后，根据可见轨迹更新 skill，供后面的题使用。官方隐藏评分不交给反思和 skill 更新器。训练中切换链、切换仓库都保留 skill；三种方式各自维护自己的演化历史。

每种方式训练后，在同一测试集上**冻结训练所得 skill**，并与**冻结初始 skill**的对照比较，两组都保留题内反思。这样既能比较三种方式的整体表现，也能判断训练中的 skill 演化是否帮助未见仓库。各组任务顺序、模型和单路预算一致，但总 token 不同，所以同时看成功率、token 和耗时。

## 数据集的构造

使用 SWE-Chain-Evo：共有 **12 个仓库、50 条链、493 个任务位置，对应 145 道不同的题**。短链与长链存在公共任务，所以位置数大于不同题目数。

主实验每个仓库选一条最长完整链，已检查覆盖该仓库全部不同任务。保留原始版本顺序，每题在一次主运行中只出现一次，避免重复做公共前缀，或先做后期版本再回到早期版本。原始 50 条链另外保留。

| 部分 | 仓库 | 题数 | 用途 |
| --- | --- | ---: | --- |
| 训练集 | click、coredns、cli、argo-workflows、sqlfluff、loki | 70 | 持续演化 skill，并用已用于开发的仓库调试 |
| 测试集 | istio、containerd、fiber、pytest | 45 | 冻结 skill，观察未见仓库上的收益 |
| 预留集 | nats-server、prometheus | 30 | 环境尚未完整缓存，本轮不使用 |

先固定训练集与测试集的仓库归属、Go/Python 题数，再分别用固定随机种子 `0` 打乱各集合内部的仓库顺序，
表中即实际顺序；仓库内保留原始链顺序。种子只控制排序，不重新分配训练／测试仓库。三种方法共用同一份清单。

目前完整缓存覆盖 115 道训练与测试任务，不需要继续导入剩余环境。训练和测试按仓库隔离，避免相同题目跨集合出现：

```text
训练 70 题：求解 → 评分 → 更新 skill → 下一题
                  ↓ 保存训练产物
测试 45 题：加载对应 skill，冻结文档，只求解和评分
```

训练中每题先评分，再更新；更新只能影响后面的题。测试期间不更新文档，但代码环境仍按历史快照变化，上一题的代码补丁不传到下一题。

可预先比较完成前 4、5、6 个训练仓库后的 skill，当前种子对应 45、55、70 题，都在完整链边界。用相同 45 道测试题评估并全部报告，观察训练增加后收益是否继续增长，不根据测试成绩只挑最好的版本。

如需重复实验，独立训练多个 skill 版本，再在固定测试清单上评估；不把改变冻结测试的排列当作演化过程。三种方式使用相同训练顺序和测试题。

训练集为 45 道 Go、25 道 Python，测试集为 40 道 Go、5 道 Python。测试只有四个仓库，先做初步收益验证；当前不增加逐次 skill 修改的性能验证。

清单位于 `tasks/splits/evoarena-frozen-v3/`，配置为 `configs/evoarena-frozen-shuffled.json`，旧版清单保留。训练跨链保留；测试用 `--initial-skill <对应训练运行目录> --fixed-skill` 加载最后采纳版本并冻结。初始 skill 对照省略加载参数，配置中也不设置 `initial_skill`。
在训练命令上加 `--test-tasks <测试清单>`，会训练完成后自动冻结测试；两阶段分别记录，三种方法均支持。
