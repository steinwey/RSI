# 轨迹证据保真与截断修复方案

## 修订

字符预算已取消。求解轨迹、选择器和更新器统一使用 `step_limit`，默认 30 步。保留的步骤和最终补丁按原文完整进入模型；超过上限时保留最近 30 步，并记录 `steps_omitted`。

## 目标与边界

原文摘录不改写；保留步骤顺序与行动/反馈关联；省略范围明确可查。有限上下文无法保证无损，但磁盘上的原始记录应尽可能完整。此次不改变技能更新策略、验证门槛或官方评分隔离规则，不启动付费模型实验。

## 实施方案

1. 新建确定性的证据整理模块。首次 assistant 行动之前的上下文按原文去重，保存并向模型提供一次；行动之后的 user 消息仍作为执行反馈保留。
2. 按 assistant 行动及随后的反馈组织步骤，保留每条原始消息的编号、长度、哈希与摘录区间。所有步骤按原顺序保留，不把后面的测试通过当作最终代码已验证的证明。
3. 优先完整保留短消息与命令、格式错误/异常/测试汇总及相邻上下文。超预算时对长消息进行原文区间摘录，保留分布在整条轨迹中的基本覆盖。选择器优先末尾验证，更新器优先失败及恢复窗口；信号仅用于排序，不作正确性判定。
4. 不按字数截断。每路最多保留 `step_limit` 步（默认 30），保留步骤和最终补丁都是完整原文。超过上限时保留最近的步骤，并用 `steps_omitted` 记录被留下的更早步数。
5. 调用模型前保存 evidence/selector.json、evidence/updater.json（完整 system/user 请求），以及 manifest.json（规则版本、请求 SHA256、预算、源日志位置和覆盖统计）。同一个请求构造函数用于实际发送与归档。原始轨迹另存 solver 可见字段的快照，防止混入官方评分。
6. 在命令输出进入上游模板之前，将执行命令、原始输出、返回码/超时与关联消息编号写入每路 commands/。保留现有求解模型的单次输出上限；这些原始日志是主机侧归档，不假称当前无工具的选择器/更新器能按路径读取。既有日志中已经丢失的输出无法追溯恢复。

## 验证与交付

- 回归测试：消息配对、原文区间与哈希、时间顺序、错误/修正与最终测试、跨文件 patch、严格预算、无源数据修改、评分字段隔离。
- 检查归档发生在模型调用前，归档请求与实际发送请求一致；模型调用失败仍留存请求。
- 检查长命令与超时输出完整落盘，归档不改变执行返回内容与退出语义。
- 对此前 25 条轨迹离线回放，保存新旧覆盖统计及新证据文件，不覆盖历史实验、不调用模型；检查明确错误反馈的原文保留率。
- 运行现有测试；在 README 中记录新日志位置与预算含义。

方案先落盘，再实施；根据离线结果调整分配算法并记录实际限制。

## 实施与验证结果

已实现 `steps-spans-v1`。消息哈希放在磁盘 manifest 中，模型输入保留来源快照哈希、消息编号、长度、步骤和原文区间，以减少重复元数据占用。能完整放入预算的内容直接完整保留。离线检查发现短格式错误可能仍被命令挤占，因此提高了短失败反馈的完整保留优先级。

对原 pilot 的 25 条轨迹使用相同的每路 16,000 字符预算回放，15 条明确非零退出或格式错误反馈中，旧方案完整保留 8 条；新选择器与更新器均完整保留 15 条。回放输出位于 `runs/evidence-replay-20261020-v2/comparison.json`，并保存了各题两个阶段的证据和来源快照；没有模型调用。66 项离线测试通过，覆盖请求与归档一致、调用失败前落盘、环境原始输出先于上游截断保存等行为。

这不是完全无损的证明：521,085 个执行阶段原文字符中，新选择器保留 297,936 个，更新器保留 298,232 个，其余通过区间及 omitted 明确标记。共享初始上下文完整保留、另计预算；总请求仍需满足实际模型的上下文限制。此前在环境或上游模板阶段丢失的输出不可恢复。新增原始命令日志只保留环境接口实际返回的数据，不保证底层环境自身从未截断。
